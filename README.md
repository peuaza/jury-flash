# jury-flash-CN

**中文 AI 文本检测器** —— 纯 CPU、无需 GPU、无需联网、无需安装 Python。

> 把一段中文文本压成 **160 维可测量的统计特征**，由一个
> **7 体裁 × 人机 = 14 类** 模型判定：**它是不是 AI 写的**，以及**它属于哪个体裁**。

当前版本：**v1.0.0**（此前的内部迭代版本均标记为 beta）

---

## 这是什么

给定一段中文文本（诗 / 散文 / 新闻 / 小说 / 科普 / 财经 / 通知 / 聊天 / 古文…），它回答两个问题：

1. **人机**：这段文字是 AI 生成的，还是人类写的？
2. **体裁**：它属于哪一类（诗 / 说明文 / 叙事 / 信息 / 古文 / 应用文 / 对话）？

特点：

| 特点 | 说明 |
|---|---|
| **纯 CPU** | 单文件 57 MB，无模型下载，普通笔记本秒级出结果 |
| **离线** | 全程不联网（除可选的本地微调） |
| **体裁 × 人机同时给出** | 判为「人类」时**也会告知体裁** |
| **三档判定** | 保守 / 温和 / 激进，可应对不同场景 |
| **可解释** | `analysis` 用**人话**说明「哪里像 AI / 哪里像人」+ 改进建议 |
| **长文研究** | `research` 对长文切片分析，给出主体裁、副体裁、AI 概率分布 |
| **可本地微调** | `learn` 用你自己的样本教它（数据留在本地） |

## 快速开始

### 方式一：双击（推荐给非开发者）

双击 `jury.exe` → 进入交互模式 → 直接敲命令：

```
jury> score -f 我的诗.txt          # 判一篇
jury> score -f 我的诗.txt -v       # 附明细
jury> analysis -f 我的诗.txt       # 人话诊断
jury> exit
```

### 方式二：命令行

```powershell
jury.exe score -f 我的诗.txt                   # 判一篇（默认温和三态）
jury.exe score -f 我的诗.txt -m auto_c         # 保守（宁可漏检也不误报）
jury.exe score -f 我的诗.txt -v                # 附 AI 类概率 / 前三类
jury.exe analysis -f 我的诗.txt                # 人话诊断
jury.exe research -f 长文.txt -c -q            # 长文深度研究
jury.exe learn -f 我的诗.txt --genre lit --label human    # 本地微调
jury.exe --help                                # 完整帮助
```

**输入要求**：纯文本，**至少 6 行**（去空行后），含足够中文。

## 命令一览

| 命令 | 作用 |
|---|---|
| `score` | 判一篇（`-f` 文件 / `-t` 文本 / `-c` 便捷模式 / `-l` 长文本模式） |
| `batch` | 批量判定（jsonl 进 jsonl 出） |
| **`analysis`** | **人话诊断**：列出最像 AI / 最像人类的特征 + 改进建议（**不给概率**） |
| **`research`** | **长文深度研究**：`-s` 切块 / `-c` 滑窗整合（`-q` 显示行首、窗口首尾） |
| **`learn`** | **本地微调**：标注「体裁 + 人类/AI」并增量重训 |
| `info` | 列出模型与当前设置 |
| `serve` | 启动本地 HTTP 服务 |
| `reset` | 清除本地微调，恢复内置模型 |

完整参数见 `jury.exe --help` 或交互模式下的 `help`。

## 判定怎么读

```
体裁判定      lit                      ← 它最像哪一类
偏向          更像 AI / 更像人类
AI 类总概率   0.000 ~ 1.000            ← 参考值，**不是概率、不可与门槛直接比较**
```

**三档模式**：

- **`auto_c`（保守）**：AI 类概率须超过较高门槛才判 AI —— 适合「误报代价高」的场景
- **`auto_p`（激进）**：只要 AI 类占优就判 AI
- **`auto_m`（温和，默认）**：两者一致才给结论，不一致则给「**不确定**」

> **建议**：不确定的样本请人工复核。工具是**辅助**，不是裁决。

## 原理（简述）

1. **特征**：145 维文本统计特征（行/句结构、标点、n-gram、词汇丰富度、token 长度分布…）
   ＋ **15 维「顺序 LM」特征**（整篇 tokenize，看跨行的 surprisal 时序结构：斜率、自相关、
   行起始 surprisal 等）＝ **160 维**。
2. **模型**：把特征标准化后送入 **14 类**（7 体裁 × 人机）模型；正式版本用
   **3 个 MLP 的集成**（隐藏层 96/128/64）。
3. **判定**：体裁与人机同时输出；判为人类时也给出体裁。

**核心设计取舍**：这套特征刻画的是**文体/统计形态**，不是「AI 性」这种普适属性。
因此**每个体裁都需要自己的训练语料**（跨体裁迁移很弱）。

## 已知局限（请务必阅读）

- **不是万能的**：对**短文本**（<6 行）直接拒绝；对**泛化的小诗**较容易误报。
- **人机边界是模糊的**：AI 与人类在统计形态上可以高度重叠（尤其当 AI 模仿某位作者的风格时）。
- **对抗脆弱性**：在**白盒 + 无限迭代**的攻击下，任何**固定统计特征集**都会被逐步绕过。
  本项目经历过完整的红蓝对抗；每轮加固都会抬升攻击成本，但不构成「不可攻破」的保证。
- **体裁定义有主观性**：例如古典小说应归「叙事」还是「古文」并无唯一答案。
- **许可与隐私**：`learn` 的标注与产物都留在本地，不会上传。
